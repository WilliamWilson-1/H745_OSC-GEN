# 800 × 480 仪表界面

本次采用 `emilkowalski/skills` 中 `emil-design-eng` 的设计原则，并针对 STM32 的 L8 显示实现：层级清晰、操作即时、动效简短、测量信息保持真实。没有引入浏览器、React、LVGL 或额外运行时。2026-09-15 将前台整屏重绘改为上下分段双缓冲，解决刷新过程可见引起的闪烁。

## 页面与交互

| 页面 | 布局与操作 |
| --- | --- |
| 主菜单 | 两张大卡片进入仪器，删除 01/02 编号；示波器卡片显示真实 ADC 缩略波形和 RUN/HOLD/WAIT；底部显示发生器输出状态与减弱动效开关。 |
| 示波器 | 保留 600 × 360 绘图区；按真实采样时间绘制 40～600 点；两侧操作按钮；底部集中显示频率、峰峰值、平均值、最高/最低电压。 |
| 发生器 | 频率、幅度为大数字卡片，触摸选中后旋转编码器修改；下方独立波形形状预览与输出状态卡片，只有右侧拨钮可操作。 |

按钮最小高度为 48 像素。绘制和点击判断共用 `UI_GetRect()` 的固定区域，动效不会移动实际点击区域。选中项同时通过边框、色块和标记线区分；输出开关有文字和拨钮，RUN/HOLD 有明确文字，不只依赖颜色。编码器按钮仍只执行当前模式复位，并显示 1 秒确认提示。

返回主菜单不会隐式关闭发生器，菜单和示波器页均显示输出状态。`Single` 沿用采集下一帧后保持的逻辑，`Wait` 表示该次采集尚未完成，不表示实现了无限等待触发的硬件单次模式。

首页和示波器共用真实 trace 渲染函数，分别映射到 312 × 70 和 600 × 360 区域。退出/进入示波器不改变采集状态，首页在 RUN 时随新帧重绘、HOLD 时保持，仍遵守原有 33 ms 绘制间隔和后台提交机制。没有 ADC 帧时不伪造数据；发生器预览仍明确属于形状说明。

示波器右侧在 SINGLE 下方加入 84 × 48 的 `Coarse` / `Fine` 互斥按钮（y=232/288），发生器状态下移至 y=350，保留底部输入范围提示。粗调使用标准档位；微调 Time/V/div 为约 10%（分别量化到 1 us/0.01 V），Trigger/Position 为 10 mV 而非粗调的 50 mV。切换模式不移动波形、不启动采集；当前模式有文字及选中标记。微调只作用于旋钮，不改变双指的标准档位缩放。

## 动效规则

| 动效 | 时长 | 行为 |
| --- | --- | --- |
| 按钮触摸反馈 | 140 ms | 小幅内缩并恢复，选择状态立即更新。 |
| 菜单/发生器进入 | 180 ms | 卡片从下方 8 像素内收至原位；示波器不做页面移动。 |
| 输出拨钮点击 | 160 ms | 松手提交，ease-out 从当前位置回位，反向点击可中断。 |
| 输出拨钮拖动 | 跟手无补间；回位最多 500 ms | 按下蓝色边框反馈，水平位移达到 10 px 后按 40 px 行程直接跟手；松手使用响应 0.3 s、临界阻尼弹簧回位，保留最近移动速度。 |
| 复位提示 | 1000 ms | 静态确认提示，到时移除，不阻塞操作。 |

波形采样点、测量数值、频率与幅度的旋钮调整不做补间。所有动画由 `UI_Tick(HAL_GetTick())` 推进，不在动画中调用延时。主循环以至少 33 ms 的绘制间隔限制重绘频率（约 30 fps 上限，不是实测帧率保证），有新采集结果时保留待刷新标志，避免 SINGLE 最后一帧因刷新限速而丢失。

`Motion: reduced` 关闭页面位移、按钮缩放和拨钮自动回位，但保留直接拖动、按下边框以及立即更新的颜色/文字反馈。该设置仅在 RAM 中保存。串口接收中断只写入 256 字节队列；协议解析、触摸动作以及 ADC/DAC 控制在主循环中执行。队列溢出或串口错误时取消当前拨动、丢弃不完整帧并在换行处重新同步。

输出卡片固定为 `(112,368,672,72)`，右侧拨钮的命中区域为 `(688,381,72,48)`（右/下边界不含）。卡片文字及空白不响应；只有在拨钮上开始的单指接触可以拖动，横向出界仍保持捕获。拖动大于 55% 置 ON，小于 45% 置 OFF，中间保留原状态；按下及移动均不改变 DAC，只有有效释放才提交。出现明显纵向意图、纵向偏离超过 24 px、多指、错误、页面离开或复位则取消。仪器开关不使用甩动速度决定通断，也不允许弹簧越过轨道边界，这是基于误开启风险对通用拖拽动效的限制。

本次交互采用 `animate`、`apple-design` 与 `emil-design-eng`：即时按下反馈、拖动跟手、可中断的短回位、测量数据不动画化。未引入网页动画库。

## 字体、颜色与内存

- 深灰背景和分层面板；绿色用于采集/运行状态，蓝色用于选中控件，黄色用于真实波形，红/青用于最高/最低电压。
- Inter Medium 字体，12/16/24/36 像素，ASCII 字符覆盖；暂不含中文字库。大数字与单位留有独立间距。
- 2-bit 抗锯齿字模覆盖数据为 41,474 字节，另有字形索引；均为 `const`，驻留 Flash。
- 800 × 480 L8 每帧 384,000 字节，两帧共 768,000 字节（750 KiB），分布在 AXI 和 D2 SRAM，详见下表。256 色调色板与混色查找表合计约 2 KiB RAM。
- 桌面预览不能验证 LTDC 时序、触摸链路、显示亮度或真实帧率；实机需要检查连续采样、快速触摸及分段交界处。

## 显示内存与同步换帧

| 区域 | 内存区间（含末地址） | 使用方式 |
| --- | --- | --- |
| CM4 | `0x30000000–0x30003FFF`，CM4 别名 `0x10000000–0x10003FFF` | 独占 16 KiB，栈顶改为 `0x10004000` |
| ADC/DAC | `0x30004000–0x30007FFF` | 独占 16 KiB `.dma_buffer` |
| 前台扫描帧 | `0x24000000–0x2405DBFF` | AXI SRAM，800 × 480 L8，384,000 字节 |
| 后台上段 | `0x2405DC00–0x2407CFFF` | AXI SRAM，第 0～159 行，128,000 字节 |
| 后台下段 | `0x30008000–0x300467FF` | D2 SRAM，第 160～479 行，256,000 字节；分区预留至 `0x30047FFF` |

LTDC 仅用图层 0 扫描完整 AXI 前台；不能让本芯片的 LTDC 图层直接读取 D2 SRAM。界面坐标仍为完整的 800 × 480，CPU 绘图按行映射到两个后台片段。

`Display_BeginFrame()` 只提供后台缓冲；`UI_Render()` 的清屏和绘图均不接触前台。`Display_Present()` 完成缓存清理后只发布完整帧。LTDC 在 `AccumulatedActiveH+1` 行中断确认进入消隐起点，再启动 MDMA：先复制上段（64,000 字节 × 2 块），再复制下段（64,000 字节 × 4 块）。两段全部完成才释放后台供下次绘制。行中断延迟到其他行时跳过本帧、等待下一消隐，禁止在可见区开始复制。

耗时绘制在后台完成，但此方案的**整帧 MDMA 复制必须在消隐期内完成**，不是只换地址。当前时序消隐预算约 1422 us；本版实机在首页与快速时基 RUN 检查中累计完成 5109 次刷新，整帧复制最大约 1055 us，未记录 FIFO、LTDC/MDMA 错误或超时。该检查期间发生器关闭，不等于完成了 ADC/DAC 同时运行压力验证。`late_copies` 非零时必须重新检查总线竞争和时序，不能宣称无撕裂。[ST AN5557](https://www.st.com/resource/en/application_note/dm00733995-stm32h745755-and-stm32h747757-lines-dualcore-architecture-stmicroelectronics.pdf) 给出了本芯片总线访问关系；此实现不使用 LTDC 双图层直读 D2 的方案。

显存使用链接脚本管理的 `NOLOAD` 区域，超出分区会导致链接失败。CM4/CM7 的 CMake 链接依赖已包含链接脚本，避免修改内存布局后仍误用旧 ELF。当前方案针对工程默认的 **Flash Debug/Release** 配置；历史 SRAM-only 链接脚本不适用于该显存布局，不应直接切换使用。

`display_stats` 提供提交数、完成数、FIFO 欠载、LTDC 传输错误、MDMA 错误、超出消隐计数、最近/最长复制耗时及消隐预算（us）。完成数在 MDMA 完成回调更新；调试读取地址必须以对应 ELF 符号为准。显示内存布局要求 CM4/CM7 一起更新，当前拨钮拖动还要求更新 F103。

字体源位于 `assets/fonts/Inter.ttf`，许可见 [OFL.txt](../assets/fonts/OFL.txt)。来源为 [Google Fonts Inter](https://github.com/google/fonts/tree/main/ofl/inter)。已提交生成字模，无需额外字体工具即可构建固件；修改字体后使用 Pillow 12.3+：

```powershell
python tools/generate_ui_font.py
```

## 实际渲染器预览与回归检查

预览直接编译 `CM7/Core/Src/graph.c`，仅替换帧缓冲地址与 ADC 状态来源，不是另写的网页或效果图。示波器截图使用测试正弦数据，不代表设备实测。

安装 Pillow 并准备桌面 GCC 或 Clang 后运行：

```powershell
python tools/preview_ui.py --cc clang
# 可选：检查主机渲染的内存访问
python tools/preview_ui.py --cc clang --sanitize
```

输出位于 `build/ui_preview/`，包括主菜单、示波器、保持/等待/极值、发生器开关/极值、复位提示、减弱动效，以及页面与开关动画 GIF。该目录被 Git 忽略，避免提交重复生成物。

检查覆盖三个页面全部 1,152,000 个坐标的按钮命中、区域不重叠/不越界、最小目标高度、动画结束、快速反向切换、关闭动效、提示到期与毫秒计时溢出。每种画面还验证连续/分段缓冲逐像素一致及缓冲保护区；另有 1,000 次模拟消隐触发 MDMA 复制，覆盖两段复制、后台所有权、重复提交保护、延迟行中断、缓存范围及错误/超时计数。

拨钮测试覆盖大框不响应、点击、左右拖动、按下/移动不提交通断、重复释放、中点死区、越界捕获、取消、页面离开和减弱动效。实际 ADC/DAC C 源码还在模拟 HAL 上检查 12 个时基、快速档真实点数、100 kHz 正弦频率计算、双边沿、SINGLE、HOLD 旧帧失效，以及 50～100000 Hz 的全部 99,951 个整数设置、DAC 更新上限和停止 DMA 后改表。它们不替代设备刷写后的 ADC、DAC 与触摸联调。

固件构建：

```powershell
.\tools\build_all.ps1 -Configuration Debug
.\tools\build_all.ps1 -Configuration Release
```

F103 通信协议新增 `D:` 单指移动和 `C:` 取消，保留 `T:/M:/U:`。本版本 H745 CM4/CM7 与 F103 需要配套更新。
